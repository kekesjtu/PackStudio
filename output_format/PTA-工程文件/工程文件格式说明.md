以下五个字段的类型出现在导出的契约中，但 PTA 3.2.1 的工程读写入口无法保存和恢复其非空值。拆分工程也使用同一序列化入口。

| 字段 | 原因 |
| --- | --- |
| `OhmContactBC.Voltage`、`SchottkyContactBC.Voltage`、`SchottkyContactBC.MetalWorkFunction` | 两种接触条件实现半导体边界接口，工程中的热边界字段接收的是热边界接口。它们仅在 `Block` 局部声明为已知类型，而块未序列化半导体边界成员。放入根级多态结果字段也会被 PTA 的工程读取器判定为未知类型。 |

## XML 语法和命名空间

- 工程文件扩展名为 `.xml`，建议使用 UTF-8。根元素为 `m:Structure`，通常把 `m` 对应的 URI 声明为默认命名空间。前缀可替换，URI、节点名和大小写须一致。
- 每张表按序列化顺序排列。**必须出现**表示 XML 契约要求该节点存在。**可省略**表示契约允许缺失，建模、加载和求解仍可能有额外要求。**可空**表示能用 `i:nil="true"` 表示空值。空字符串、空集合、空值和缺失节点分别有不同的含义。
- 表中的元素继承所在类型的命名空间。字段的 **XML 类型**若属于另一命名空间，字段元素仍在原命名空间中，该类型的内部字段和集合条目使用各自的命名空间。例如 `m:GeneratedMesh/g:XArray/a:double`。
- `xs:string` 可存纯文本或相应字段接受的表达式。数字小数点用 `.`。常用的 `xs:double`、`xs:float`、`xs:int` 分别为双精度浮点数、单精度浮点数和有符号 32 位整数，`xs:unsignedByte` 为 0–255 的整数，`xs:boolean` 通常写 `true` 或 `false`。
- 通过 `i:type="前缀:类型"` 写入运行时类型。字段本身无需改名。生成动态类型、表达式、几何引用和结果字段时，还需满足相应数据的业务约束。直接编辑已有工程时，应保留未编辑字段的值与顺序。

## 几何、拓扑与颜色

- 独立块工程把块放在根级 `Blocks`。分层工程把块放在 `Layers/Layer/Blocks`。分层工程的 `TopLayerIndex` 必须指向有效层。PTA 打开工程时会用顶层层厚填充该层厚度表达式为 `0` 的块。
- 几何坐标、厚度、偏移、阵列间隔和网格尺寸取工程的 `LengthUnit`。新建独立块应有正厚度和至少一个正向矩形，正向矩形的宽高应为正数。
- `ParentBlock` 和 `ParentRect` 嵌套完整的来源对象。保留原文件的层级关系，避免构造循环引用。

## 边界与边界条件

`Boundary/ThermalBoundary` 和根下的 `TopThermalBoundary`、`BottomThermalBoundary`、`OtherThermalBondary` 在 XML 中以 `xs:anyType` 表示。可写入下列六种热和流体边界条件。设置边界时应提供该类型所需的物理字段。`TopThermalBoundary` 和 `BottomThermalBoundary` 用于兼容旧工程。新建按面边界写入 `Boundaries`。

边界面通过 `FaceKeys` 或旧版 `FaceIds` 关联。加载旧文件时 PTA 会尝试从索引迁移到面键。外部编辑时沿用 PTA 保存的面键，几何变更后重新核对关联面。

例如，指定顶面恒温时，`TopThermalBoundary` 元素属于模型命名空间，而 `Temperature` 属于边界条件命名空间。以下片段假定外层已声明 `m`、`b`、`i`。

```xml
<m:TopThermalBoundary i:type="b:FirstTypeThermalBoundary">
  <b:Temperature>300</b:Temperature>
</m:TopThermalBoundary>
```
