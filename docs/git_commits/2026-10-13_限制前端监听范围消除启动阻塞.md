# 提交说明 — 2026-10-13

## 变更概述

限制 Vite 文件监听范围，消除开发模式启动时遍历 Python 环境、打包产物与参考数据造成的长时间阻塞。

## 变更详情

### 根因与修复
- 用户日志中开发界面等待 35.2 秒；对应前端日志包含配置缓存失效和依赖预打包提示。
- 使用独立空缓存复现前端准备 34.208 秒，Node CPU 采样中约 31.6 秒位于
  `node:internal/fs/watchers` 的 `FSWatcher` 初始化。依赖打包的墙钟时间包含监听器阻塞，
  不能将全部等待归因于打包计算。
- Vite 默认监听仓库根目录，实际遍历 `.venv`、`release`、`tmp`、参考数据等目录。
  这也阻塞了 HTTP 就绪接口，产生连续的单次检查超时。
- 在 `vite.config.ts` 中按项目根目录排除后端、Python 环境、缓存、打包、文档和参考目录。
  前端源码、样式、public、工具配置继续监听；后端源码和参数库仍由 Uvicorn 监听。

### 验证工具与文档
- 新增独立缓存基准工具，连续测量空依赖缓存与缓存复用；自动选择空闲端口并清理自己的缓存。
- 新增实际 Vite 监听器回归测试，断言排除目录未遍历，源码、CSS、配置、public 修改及
  新增源码文件仍被检测到。测试夹具置于 `tmp`，同时验证忽略规则不会误匹配项目祖先目录。
- 更新 ADR-0023，记录原因、监听边界和复测命令。

完整脚本中后端初始化约 2.6 秒，其后开发界面检查显示 0.0 秒，因为前端已并行准备完毕。
独立基准从 Vite 服务创建到页面模块和依赖就绪计时，不包含进程模块导入、浏览器启动或
WebGL 渲染；空依赖缓存不等同于操作系统磁盘冷缓存。数据仅代表本机实测，不作固定性能保证。

日志没有足够信息追溯此前配置缓存失效的每个来源；本次解决的是缓存失效时暴露的文件监听
阻塞，保留 Vite 正常的缓存失效机制。
