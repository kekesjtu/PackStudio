# 提交说明 — 2026-10-13

## 变更概述

明确浏览器在服务准备后自动打开的流程，改善停留在“正在启动 PackStudio”时的可诊断性和本机就绪检查。

## 变更详情

### 启动脚本
- 自动打开浏览器逻辑保留，增加明确的打开提示；系统打开网址失败时显示警告和可手动访问的网址，服务继续运行。
- 模板库初始化、开发界面准备、前端 API 连接分别显示阶段和耗时；等待较久时每 5 秒显示最近的检查结果。
- 使用直接连接本机的 HttpClient，禁用代理，设置每次请求 2 秒超时，读取响应体完成后才认定就绪。
- 就绪检查独立为 `tools/wait_for_endpoint.ps1`，保留进程退出检测与阶段超时；脚本使用 UTF-8 BOM 兼容 Windows PowerShell 5.1。
- 服务标准输出与错误写入 `tmp/startup/<后端端口>-<前端端口>/`，启动失败时显示日志尾部；不同端口的实例不共用日志文件。
- README 说明自动打开的时机、关闭自动打开的参数及失败日志位置。

## 备注

用户终端停留在“正在启动 PackStudio”，说明尚未执行服务就绪之后的浏览器打开操作。
本机未复现普通模式自动打开失败，因此不能断言原等待是由代理或某个服务错误造成。
普通模式实际自动打开成功，模板初始化约 2.6 秒；普通模式完整检查及清理约 4.4 秒。

开发模式依赖缓存缺失时，真实预打包曾使前端检查等待约 42.8 秒；随后缓存启动检查通过。
本次改善等待提示与检查可靠性，没有消除首次依赖预打包的成本。
Windows PowerShell 5.1 最终开发模式完整检查及清理约 5.3 秒。
耗时受缓存和机器负载影响，不作为固定性能保证。
