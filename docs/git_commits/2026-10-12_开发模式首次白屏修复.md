# 提交说明 — 2026-10-12

## 变更概述

修复 `start.ps1 -Dev` 每次启动后首次打开浏览器长时间白屏、刷新后变快的问题。

## 变更详情

### CSS 与依赖准备

- 项目使用普通 CSS，显式声明空 PostCSS 插件列表，避免首次样式处理向上搜索外部配置。
- 使用 TypeScript 导入解析自动收集前端依赖，加入 React 的运行时入口，只预打包实际前端依赖。
- 固定 HTML 入口，并关闭整个仓库的自动依赖发现，避免额外解析发行包与参考/临时文件。
- 生产构建缓存把 `src/tooling` 纳入输入指纹。

### 开发服务生命周期

- `npm run dev` 使用 Vite API 启动，显式并行准备项目页面文件，避免递归预转换全部第三方依赖。
- 等待依赖包处理并预热 HTML 后，专用接口才返回 HTTP 200 和 `{ready:true}`；准备期间返回 503。
- 就绪中间件注册在 HTML 回退处理前，防止接口未就绪时被回退页面的 200 冒充。
- `start.ps1 -Dev` 等待前端就绪后才打开浏览器；错误时关闭服务器，保留进程树清理。
- Fast Refresh、源码映射及现有界面/导出行为保留。
- README 与 ADR-0023 补充开发模式准备流程、缓存和新增依赖后的重启要求。

## 证据与限制

临时分阶段计时中：其余页面文件转换约 0.07–0.30 s；两份 CSS 首次处理分别约
21.518 / 21.519 s。显式 PostCSS 配置后，同样式转换约 0.073 / 0.074 s。
项目文件显式准备及 HTML 预热避免额外依赖树递归工作，缓存下前端准备约 1 s。

最终 `start.ps1 -Dev -Check -NoBrowser` 从调用到关闭测试进程实测 **4.892 s**。
强制重新预打包并就绪后，在新浏览器地址使用仅临时注入的探针，完整界面出现时间为
**1.405 s**，包括两帧等待；116 个资源、约 14.45 MB 解码体积，开发源码映射仍保留。
该页面计时不含终端准备、外部浏览器进程启动；首次预打包和机器负载会影响总时间。
