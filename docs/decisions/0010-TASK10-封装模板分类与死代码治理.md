# ADR-0010：按封装类别建立模板边界并删除不可达前端

## 日期

2026-07-30

## 状态

已采纳。

## 背景

八类模板在 TASK9 后已经具有较高几何保真度，但所有文件平铺在同一目录，使共享设施和具体
封装之间的依赖不清晰。与此同时，应用已统一使用 `PackageWorkspace`，旧 Flip Chip CBGA
专用工作区仍保留在源码中，却没有生产入口。这两类问题都会让后续修改者难以判断代码归属和
真实使用状态。

## 决策

### 1. 模板目录按职责分层

- `core` 只能承载至少被两个封装类别共享的契约、生成流程和通用矩形基元。
- `bga` 承载焊球阵列封装及 BGA 层构造。
- `flip_chip` 承载两类 Flip-chip 模板、顶部结构和强制正交各向异性凸点等效层。
- `leadframe` 承载 QFN/QFP/SOIC 和各自引线框基元。
- `bare_die` 保持独立。
- 根 `catalog.py` 是具体模板的唯一汇聚点，根目录不保留旧路径转发模块。

Flip-chip 封装可以依赖 BGA 层构造，因为其底部焊球就是明确的 BGA 子结构；类别模板不能
反向依赖 `catalog`。

### 2. 前端按当前产品职责组织

当前八类向导保留在 `features/package-library`，可跨模板复用的预览、模型树、材料字段和
布局控件归入 `features/model-editor`。不再保留以旧单模板产品流程命名、但从应用入口不可达
的组件树。

### 3. 死代码必须基于可达性证据删除

- 从 `main.tsx → App → PackageWorkspace` 检查生产导入链。
- 结合 TypeScript 导出引用、Python 定义引用、Ruff、ESLint 和 CSS 类引用审计。
- 由已删除模块唯一消费的代码和测试一并删除。
- 框架通过装饰器注册的路由不能仅凭函数名引用次数删除。
- 仍被兼容 API 或共享阵列算法调用的后端 Flip Chip CBGA 包明确保留。

### 4. 用结构测试防止再次平铺

自动化测试必须导入八类类别模块，并断言 `package_library` 根目录只存在注册入口和包初始
文件。模板移动后，既有 8 类基准、320 个数值变体和顶部结构回归仍必须全部通过。

## 理由

建立无业务含义的超大 `common` 目录不能解决边界问题，而按封装物理类别分组能让字段、几何
和材料修改具有清晰作用域。对于已经不可达的旧界面，保留“以防以后使用”只会造成两套流程
并存；Git 历史已经提供恢复能力。结构测试则把一次性整理转化为长期约束。

## 结果

- 八类生产模板有稳定类别位置，共享与专用代码边界清晰。
- 旧专用前端组件链及其无引用样式被移除。
- 现行 API、模板 ID、请求格式、几何、材料和 PTA 导出行为不变。
- 后续新增模板必须选择现有物理类别或通过新的 ADR 建立类别。
