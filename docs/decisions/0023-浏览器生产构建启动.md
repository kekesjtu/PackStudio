# ADR-0023：浏览器默认使用可缓存的生产构建

日期：2026-10-12。状态：采用。

## 背景

模板初始化优化后，用户仍反馈首次完整界面加载慢。浏览器实测开发服务加载约 27.3 MB
解码资源，其中包含大型 UI/三维库和内嵌源码映射；无 Vite 缓存时完整界面出现约需 6.3 s。

## 决策

- `start.ps1` 默认在本机用 Vite preview 服务 `dist`，保留 5173 端口和 API 代理。
- 首次或输入文件变化时执行 `npm run build`；其余启动校验输入和输出哈希后复用产物。
- 输入包括前端源码、public、依赖声明与锁文件、Vite/TypeScript 配置和 HTML；损坏的输出不复用。
- `-Setup` 强制重建，`-Dev` 保留 Vite 开发服务与热更新，并预热入口模块。
- 浏览器打开前等待默认模板 schema 成功，使“已就绪”包含模板初始化。
- MUI 控件使用公开的组件路径；主题 API 使用 styles 入口；drei 只导入使用的五个控件。

## 影响与限制

浏览器仍使用原端口，保存参数的 origin 不变。前端源码修改在默认模式下需重新启动；开发使用
`-Dev`。首次构建和源码变化后的构建有一次准备开销。preview 仅用于本机启动，不作为公开部署
服务器；已有 Electron/FastAPI 静态前端托管和打包方式不变。

依据：[Vite 性能指南](https://vite.dev/guide/performance)、
[MUI 导入性能指南](https://mui.com/material-ui/guides/minimizing-bundle-size/)。

## 开发模式补充（2026-10-12）

开发模式首次白屏的实测阻塞点包含两份 CSS 的首次处理：约 21 s，而其余页面源码约 0.3 s。
项目没有 PostCSS 插件需求，显式设置空插件列表，取消向上查找外部配置；该段样式处理降至约 0.07 s。

开发入口通过 Vite API 准备实际页面文件和 HTML，等待依赖包处理完成后才发布就绪状态。
不递归预转换整个依赖树；第三方依赖列表从前端 TypeScript 导入自动收集，避免扫描发行包和参考目录。
`start.ps1 -Dev` 等待专用就绪接口，保留 Fast Refresh 与源码映射。
新增依赖后需重启以更新预打包列表；引入 PostCSS 插件时须在 Vite 配置中显式声明。

依据：[Vite 内联 PostCSS 配置](https://vite.dev/config/shared-options#css-postcss)、
[Vite 依赖优化配置](https://vite.dev/config/dep-optimization-options)。

## 开发模式文件监听范围（2026-10-13）

独立空依赖缓存下仍复现前端准备约 34 秒。Node CPU 采样显示约 31.6 秒落在
`FSWatcher` 初始化：Vite 默认监听项目根目录，连同 Python 虚拟环境、桌面打包产物、
临时测试输出和开发参考数据一起遍历。监听器初始化阻塞事件循环，依赖打包和 HTTP
就绪检查同时被拖慢；仅调整缓存或延后打开浏览器不能解决此问题。

Vite 的 `server.watch.ignored` 排除上述目录及后端源码、参数库、文档和图片参考；
规则限定在当前项目根目录内。前端源码、样式、工具配置和 public 静态资源继续监听，
后端与参数 JSON 的热重载继续由 Uvicorn 负责。

使用 `node tools/benchmark_frontend_startup.mjs` 对比空缓存和复用缓存的前端准备时间。
基准工具使用随机独立缓存和系统分配的端口，结束后清理自己的缓存，不覆盖日常开发缓存。
这些时间不包含后端初始化、浏览器加载和 WebGL 渲染。
