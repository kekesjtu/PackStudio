# 预设与方案统一契约及四层配置

## 完整方案契约

普通预设是随应用分发的预制方案，与用户保存的可导入方案采用相同 JSON 契约、数据结构与读取入口。FloXML 是面向下游求解软件的模型输出，不承担方案导入。

方案格式为 `packstudio.project/v4`，正文包含 `SchemaVersion`、`TemplateId`、`Name`、`Values`、`MaterialAssignments`、`CustomMaterials`。

- 内置预设的 `Name` 使用预设目录中的名称，例如 `PBGA_196_15X15mm`；索引键与该名称一致。
- `TemplateId` 标识封装家族；方案不保存预设来源、预设 ID、预设分支或 `footprint.size`。
- `Values` 保存方案参数与实际层表，保留 `null`、`0`、`false` 的各自语义。
- `MaterialAssignments` 是每个组件材料组的完整选择，不是覆盖预设的差量；缺少材料组应报错。
- `CustomMaterials` 保存方案自定义物性，包括用户明确编辑的等效材料物性。材料库记录通过材料 ID 引用。

选择普通预设创建方案时，复制其参数、完整材料选择与自定义物性；用户输入具有最终优先级。Bare Die 从模板基线创建，并将默认材料选择写入方案。

导入完整方案直接恢复文件中的参数和材料选择，不重新执行预设初始化、四层初始化或材料预设覆盖。兼容输入的版本迁移仅发生在文件读取边界；兼容文件需要的默认材料在该边界解析为完整选择。

## 四层配置小契约

Chip Array 与 Wirebond PBGA 的四层初始化使用独立的 `packstudio.four-layer/v1` 小契约，文件位于 `runtime_data/presets/<family>/four_layer.json`。

四层配置不是完整方案，不进入普通预设索引，不作为方案文件导入。它只描述该家族四层初始化的独特行为：

- `schema_version` 与 `family` 标识契约和家族。
- `values` 保存共用的四层层表、基板厚度，以及该家族需要的层数、通孔行列设置。
- `preset_values` 以普通预设 `Name` 为键，保存随具体封装变化的散热片长宽。

Core 为支持的家族提供明确的四层初始化代码分支。仅在用户于创建阶段显式选择 `substrate.layers = "4-Layer"` 时读取家族四层配置；普通预设加载、两层创建、方案导入和模型生成不读取它。CLI 中显式提供相同创建选项具有一致语义。

初始化顺序为：普通预设参数 → 四层共用设置 → 对应预设的四层差异 → 用户显式输入 → 层栈计算。四层配置不修改焊球布局和材料选择。

用户显式提供的层表具有优先级；其他情况下按创建参数计算层栈。完成创建后，方案中的层表直接参与建模。切换回两层时从所选普通预设重新初始化，并保留用户显式输入。

## 露出焊盘配置小契约

SOP 与 PQFP 的露出焊盘初始化使用独立的 `packstudio.exposed-pad/v1` 小契约，分别位于 `runtime_data/presets/tsop_conv/exposed_pad.json` 与 `runtime_data/presets/pqfp/exposed_pad.json`。

- `schema_version` 与 `family` 标识契约和内部家族 ID。
- `values` 只包含 `thermal_land.enabled` 与 `thermal_land.thickness`，厚度单位为 mm。
- `flag_downset_source` 是 `flag.downset` 的来源参数键，使用 `leads.height`；初始化按此引用复制参数，小契约不承载通用条件或复制脚本。

仅在完成创建且最终选择 `package.exposed_pad = true` 时读取和应用。普通预设加载、弹窗编辑、方案导入与模型生成不读取该配置。初始化顺序为普通预设 → 露出焊盘设置及位置复制 → 用户显式输入；`null`、0、false 和与预设相同的显式输入均保留，不执行业务校验。

该配置不进入普通预设索引，不作为完整方案导入。参数定义不保存露出焊盘初始化声明。Desktop 和 CLI 采用相同的创建语义。
