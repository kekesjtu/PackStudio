# ADR-0007：TASK7 生产模板与参考数据解耦

## 日期

2026-07-29

## 状态

已采纳。本 ADR 替代 ADR-0006 中“运行时只读参考适配层”和“根据变体 FloXML 动态 patch”
的决策；ADR-0006 记录的数据证据、特殊层约束和基准复核结论仍然有效。

## 背景

`flotherm_pack_data` 是开发期间取得的参考资料，其目录结构、注册表和 FloXML 不属于
PackStudio 运行契约。如果生产请求必须读取这些文件，部署包就无法独立运行；参考归档格式
变化也会在未修改生产代码的情况下改变软件行为。

## 决策

### 1. 参考数据不进入运行路径

- 生产模块不得定位、读取或解析 `flotherm_pack_data`。
- 参考目录只用于工程师核对默认值、尺寸、材料和单变量效果，以及开发期回归。
- 从参考资料吸收新行为时，必须修改生产模板代码、测试和文档。

### 2. 八类模板在生产代码中显式实现

- 每个模板拥有独立 Python 模块和 `TemplateDefinition`。
- 字段的 key、步骤、控件、默认值、范围、选项和条件均为显式代码。
- 几何生成器使用命名参数和公式构造基板、芯片、塑封、引线、焊球等结构。
- 公共算法只负责材料、矩形差集、热源、边界、分组和导出，不保存模板几何数据。

### 3. 使用稳定的生产 schema

- schema 升级为 `packstudio.wizard/v2`，字段状态为 `implemented`。
- 模板目录公开 `implementation_status=packstudio_native` 和
  `runtime_reference_data_required=false`。
- 参数范围属于 PackStudio API 契约；参考数据更新不会自动扩大范围。

### 4. 材料库内置

- 生产代码提供经过参考数据校准的内置材料对象。
- 材料 ID 是 PackStudio 稳定 ID，不复用 FloXML 哈希 ID。
- 用户仍可编辑材料或按结构组重新绑定；导出仅包含实际使用的材料。

### 5. 删除动态参考适配器

- 删除 reference repository、FloXML parser、variation patch、动态材料读取和场景转换器。
- `/api/templates/reference/*` 暂作隐藏兼容别名，但与主 API 调用同一个原生生成器。
- 前端仅使用 `/api/templates/{template_id}/*`。

## 结果

- 部署时可以完全不包含 `flotherm_pack_data`。
- 模板行为只随生产代码版本变化，可审查、可测试、可迁移。
- 参考资料与实现之间不再自动同步；这是有意的安全边界，也是后续维护需要承担的显式工作。
- 八类模板共享基础设施，但每类封装结构和参数规则仍能在对应模块中独立阅读和修改。

## 验证方式

自动测试将所有 `Path.read_text` 和 `lxml.etree.parse` 替换为立即失败函数，再依次执行八类
生成与 PTA 导出。该测试通过意味着生产请求没有通过文件读取器间接依赖参考资料。
