# ADR-0006：TASK6 八类证据驱动模板

> **状态更新（2026-07-29）**：ADR-0007 已替代本文的运行时参考适配与动态 FloXML patch
> 方案。本文的数据证据、特殊层约束和 Flip Chip CBGA 基准结论继续有效。

## 日期

2026-07-29

## 背景

TASK1–5 已建立统一领域模型、Flip Chip CBGA 工作区、材料绑定、仿真输入和组合焊球规则，
但其他封装仍未进入生产主线。`flotherm_pack_data` 已完成 8 类模板的 UI、589 项参数注册表、
8 份基准 FloXML、656 组单变量差异、779 次导出证据和 48 项材料定义。直接手写八套几何
会重新引入无法追溯的猜测，也无法可靠表达 PACK 的条件字段和变体效果。

## 决策

### 1. 建立只读参考适配层

- 以模板目录、参数注册表、覆盖清单、基准/变体 FloXML 和主材料库作为运行时只读证据。
- 基准 FloXML 解析为独立场景对象，再转换为 PackStudio 领域模型；不直接复制成 PTA 输出。
- 参数 schema 只开放已回放且已分析的目标。枚举只接受回放值，数值仅在双侧证据区间内插。
- UI 和后端共同执行 `visible_when`、`enabled_when`、`hidden_when` 条件，后端拒绝绕过向导
  提交的未激活分支参数。
- 模型元数据记录 PACK 版本、基准路径、覆盖项和证据级别；多个覆盖项明确标为“分别验证
  效果的组合”，不宣称是 PACK 对该组合的整体回放结果。

### 2. 统一为无重叠笛卡尔矩形块

- 递归累加 FloXML assembly 坐标，将 cuboid 统一到 mm、右手笛卡尔坐标系。
- 更小、更具体的嵌入结构优先；对被嵌入的轴对齐 cuboid 做确定性矩形差集分割。
- 生成后的所有块必须具有正尺寸、有效材料与分组，且不得存在正体积重叠。
- 芯片功率按芯片块体积比例分配；环境、PCB 侧、顶部边界沿统一领域契约生成。

### 3. 特殊层由 PackStudio 规则替代 PACK 选项

- 仅四类 BGA 模板的焊球层提供 `equivalent` 和 `discrete`。
- BGA 默认隐式正交全阵列，只保留可组合的中央焊球、中央去球和显式去球；优先级、静态
  空气和矩形分区沿 ADR-0005。
- 两类 Flip-chip 模板删除 PACK 的凸点表达选项，始终生成有厚度的正交各向异性
  bumps + underfill 等效层；组分使用手工验证的 Pb90/Sn10 焊料和 Underfill。
- API 与 schema 拒绝交错阵列、solder-ball map、PACK 凸点/焊球表达和 underfill 开关，
  防止同一结构出现冲突语义。

### 4. 保留旧路由并增加统一参考路由

- TASK2–5 的 `/api/templates/flip-chip-cbga/*` 暂时保留，继续服务旧参数预设和兼容测试。
- 新主线使用 `/api/templates/reference/{template_id}/*`，统一提供 schema、defaults、
  generate 和 PTA export。
- 前端模板选择器和通用工作区使用新路由；本地保存键包含 schema 版本和模板 ID。

### 5. PTA 导出按全局 Z 边界切片

- 导出器收集全部块的 Z 边界，将跨多个高度区间的块切成逐层片段。
- 全局 Z 区间必须连续；空层或不连续堆叠在导出前拒绝。
- 导出继续只包含几何、材料、源项、边界和最大网格尺寸，不包含网格实体与求解结果。

## 结果

- 八类模板共享同一向导、材料/热源/边界和预览框架，不需要修改核心领域模型。
- Flip Chip CBGA 基准被修正为 6 × 6 × 1.15 mm 基板、5.3 × 5.3 mm BGA 包络、
  1.8 × 1.8 × 0.1 mm 凸点等效层，以及焊球层 -0.4 mm 至基板底面的 Z 堆叠。
- 所有基准模型和导出由自动测试覆盖；QFN 等复杂嵌入结构会产生较多矩形差集块和较大的
  PTA 文件，这是保持轴对齐、无重叠表达的直接代价。

## 未解决项

- 仍需在下游 PTA GUI 中对八类代表文件执行导入、网格生成和稳态求解人工验收。
- 前端主 JavaScript chunk 超过 500 kB，后续可按预览/材料编辑器拆分加载。
- 未经组合回放的多参数组合只保证 PackStudio 领域约束和各单变量效果，不保证与 PACK 的
  组合求值完全一致。

本 ADR 补充 ADR-0001–0005；若特殊层规则冲突，以本 ADR 和 TASK6 的强制约束为准。
