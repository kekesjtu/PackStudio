# ADR-0012：用手写尺寸预设实现 FloTHERM PACK 风格向导

## 日期

2026-07-31

## 状态

已采纳。

## 背景

FloTHERM PACK 的建模流程先选择 Standard Outline 与 JEDEC Footprint，再进入与封装结构对应
的步骤。PackStudio 已经手写转录了八类默认几何，却仍要求用户从一组通用数值字段开始，
尺寸之间没有标准外形联动。直接在运行时读取参考 JSON 会重新引入 TASK7 已消除的部署依赖；
照搬 Outline Type、Thermal Die、Collapsed Cuboid 等全部自由度又会违背 PackStudio 的受控
模板定位。

## 决策

### 1. 固定行为不渲染为单值选项

- `outline_type` 始终为 `standard_outline`。
- `die_type` 始终为 `actual_type`。
- 两项写入 schema 特殊规则和模型元数据，供审计使用，但不占用左侧表单。
- 建模页只显示会改变生成结果且确实受支持的选择。

### 2. 尺寸预设是生产代码的一部分

每个封装类别在自己的 `footprints.py` 中声明 `PresetOption`：稳定值、中文显示名，以及需要
联动的生产字段。每个 JEDEC 项是独立的结构级默认值集合，必须包含芯片 X/Y，并按该变体的
证据分别声明塑封体、承载台、阵列或引脚参数；不得把整个模型乘以统一缩放系数。schema 将
关联字段转换为完整 target ID；后端先应用预设，再应用用户显式覆盖。前端使用同一 schema
即时显示联动值，切换预设时清除旧预设下的尺寸覆盖。

预设不读取参考文件。生产下拉仅保留默认基准和开发期已经捕获 FloXML 的代表性变体；各项
数值由对应 FloXML 几何差异逐项转录。当前 7 类 JEDEC 模板各有 3 项，Bare Die 另有 4 个
芯片尺寸快捷预设，共 25 项。未捕获的厂商目录项不进入生产下拉。

### 3. 向导按参考物理步骤组织

所有模板先显示“概要”和“封装规格”，随后按封装类别排列基板、塑封、芯片、凸点、焊球、
承载台、DAP、引线框、键合线等页面。BGA 的焊球去除与中央焊球保留为独立步骤，建模方式
放在统一“建模选项”页；边界条件仍作为 PackStudio 求解前扩展置于末尾。

界面标签以中文为主，JEDEC、BGA、DAP 等行业标识和标准 footprint 编号保持原标识，避免
翻译后失去可核对性。

### 4. 阵列与凸点自由度收紧

- 只有 `has_bga=True` 的模板提供 BGA 正交各向异性等效层和离散建模两种选择。
- BGA 排布仍隐式为正交全阵列，只开放可组合的去球和中央焊球。
- Flip-chip bumps + underfill 固定为有厚度的正交各向异性等效层。
- Bare Die 启用 bumps 时使用相同的厚等效层原则。
- 所有生产 schema 均不出现 collapsed cuboid。

### 5. QFP/SOIC 使用散热焊盘与焊料语义

QFP 和 SOIC 删除 `exposed_pad.enabled`，改为 `thermal_land.enabled`。启用后在封装下方生成
独立散热焊盘与焊料块，材料分别受组件白名单约束。旧保存方案中的 exposed-pad 字段由现有
schema 过滤机制自然丢弃，不建立双字段兼容层。

## 理由

把预设作为有类型的生产定义，可以同时服务 UI 即时联动、API 校验和模型生成，并保持参考
数据可从部署包删除。隐藏固定行为比显示只有一个值的禁用下拉更符合用户的建模心智；保留
显式尺寸覆盖则避免 JEDEC 预设阻断实际工程公差和定制需求。

## 结果

- 八类模板共有 25 个可生成尺寸预设，默认几何与既有 FloXML 基准不变。
- 左侧导航与 FloTHERM PACK 的组件步骤基本对应，但不复制其过度灵活或本项目禁止的分支。
- schema 成为预设联动的唯一前后端契约，运行时仍与 `flotherm_pack_data` 解耦。
- QFP/SOIC 的用户术语、材料入口和生成实体统一为散热焊盘与焊料。
