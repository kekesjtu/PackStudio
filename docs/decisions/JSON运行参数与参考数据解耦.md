# JSON 运行参数与参考数据

## 决策

生产运行从 `runtime_data/` 读取封装定义、内部格式预设、选材与材料物性，运行库随源码和桌面分发包发布。
应用通过自身运行库完成模型生成，缺失或无效的数据通过校验错误返回。

每种封装使用一份 definition，以 `keys` 统一声明参数、材料选择、选项及展示配置，以 `steps` 组织向导栏目。数据类型驱动控件与解析，选项的保存值与显示名称在同一记录中定义；内部字段不声明展示栏目。DES 条件符号随封装参数分支选择，业务校验规则独立放在 `validation/`。
正式预设采用完整方案契约，直接保存内部字段及规范化值、完整材料选择；焊球与阵列配置作为 `bga.*` 参数统一保存在 Values 中。四层初始化使用家族目录下的独立小契约，仅由显式创建选择触发读取。
单位、枚举、原生状态、材料名、派生表格和保留球位补集在提取阶段处理，生产运行不执行原生属性路径投影。

原生中间记录、完整源文本、DLL 信息和临时迁移脚本属于研究产物，使用任务专属临时目录。
正式预设不携带原生来源或预设来源字段。内部字段、DES 键、PACK 组件及脚本属性的对应关系维护在 docs/ 的人工对照表及同主题 JSON 中。
文档供核对与临时提取使用，产品不依赖文档，也不维护另一张运行绑定表。

## 依据

运行数据与内部领域模型使用相同语义，独立部署不需要原生安装或研究工具。
来源证据与运行输入各自维护，避免原生存储结构、状态包装及脚本命名进入产品数据加载流程。
几何、初始化联动与覆盖优先级由生成代码及回归测试约束。
