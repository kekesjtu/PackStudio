# PackStudio 数据流与架构

本文定义参数化封装建模的数据流、模块职责和运行数据边界。Desktop 与 CLI 通过进程内调用共享 Core；生产应用不依赖本地 HTTP 服务、Python、Flotherm PACK 安装或研究归档。

## 1. 架构原则

- 初始化负责创建方案和一次性参数合成；建模负责几何、等效物性、热源与几何元数据计算；校验负责返回结构化问题。
- 创建方案允许保留缺失或不合理的业务输入。完整输入校验在请求生成模型时执行，创建成功不表示参数已通过校验。
- 参数定义提供字段语义与简单约束，C# 提供跨字段关系、家族与组件规则。UI 展示条件与业务生效条件分别维护。
- 文件读取、反序列化、契约结构检查、显式版本迁移和文件输出集中在读写边界。初始化、建模和校验通过参数接收数据，不访问文件。
- 方案持有用户实际值；生成使用方案快照，模型携带实际使用材料的快照。校验不修正参数或几何，生成不反向修改方案和材料库。
- 一个流程入口组织调用并汇总结果，不为转发参数增加服务、重复状态容器或通用工作流、表达式引擎。

## 2. 运行数据与权威来源

`runtime_data/` 随应用分发，负责提供参数定义、预设、材料和目录元数据。文件按家族 ID、参数键、材料 ID 和模型组 ID 建立关联；读取边界检查契约版本、结构和必要引用，配置缺失或损坏应明确报告。

| 数据 | 权威内容与使用边界 |
| --- | --- |
| `definitions/<family>.json` | 稳定参数键、类型、单位、枚举、必填与数值范围、表格约束、业务生效条件、创建阶段属性、Bare Die 基线、材料槽位及建模选项；同时声明标签、符号、栏目、示意图路由和 UI 显示配置。 |
| `presets/index.json` | 普通预设名称、家族和完整方案文件路径。 |
| `presets/<来源目录>/<预设名>.json` | 完整方案参数、材料选择与自定义材料，使用与用户方案相同的契约。 |
| `presets/<family>/four_layer.json` | Chip Array 与 Wirebond PBGA 的四层创建配置，保存共用设置和逐预设差异；仅在完成创建且选择四层时读取，不进入普通预设索引。 |
| `presets/tsop_conv/exposed_pad.json`、`presets/pqfp/exposed_pad.json` | SOP 与 PQFP 的露出焊盘创建配置；仅在完成创建且启用对应选项时读取，不进入普通预设索引。 |
| `materials/<分类>/<材料>.json` | 来源材料的物性字段、明确的导热类型和来源信息。 |
| `materials/index.json`、`materials/runtime.json` | 材料目录、文件路径、内部别名、颜色和项目补充材料。 |
| `families.json` | 家族 ID、名称、分组、描述、图标、默认选择和示意图样式。 |
| `model_groups.json` | 稳定模型组 ID、父子关系和名称，供建模、模型树与导出共用；与材料分类分开。 |

字段的 `required`、`minimum`、`maximum`、`exclusive_minimum`、`min_rows` 和 `max_rows` 直接放在参数定义中；嵌套对象与表格列的约束随子字段声明。业务生效条件使用 `active_when`、`inactive_when`、`requires_numeric` 和 `requires_positive`，不能根据控件是否可见推断字段是否参与建模。

跨字段关系、家族与组件规则、模型有效性检查、诊断编号、严重度和消息由 C# 定义。运行数据不声明检查器、不注册算法，也不承载脚本或任意公式。材料的基本数值要求由共用代码实现，供读取边界、输入校验和模型校验复用。

完整方案保存实际参数、`MaterialAssignments` 和 `CustomMaterials`，不保存预设来源、创建分支来源或用于反复初始化的覆盖历史。普通预设缺少必要字段时报告问题，不使用 UI 配置隐式补齐。

## 3. 数据流

### 3.1 创建方案

```text
NewPackage 编辑阶段
    记录家族、预设、创建选项和用户输入
    → 字段编辑与选项切换只更新创建请求
        ↓
点击“完成”（CLI 可提交相同语义的创建请求）
        ↓
完整方案预设 / Bare Die 参数基线
    + 参数定义与材料默认选择
    + 根据最终选项按需读取的创建配置
    + 用户提交的参数
        ↓
PackageInitializer（执行一次）
    复制预设或基线
    → 应用创建分支设置
    → 应用用户参数覆盖
    → 计算创建层栈
        ↓
ProjectDocument
        ↓
主界面参数编辑 / CLI 后续操作
```

NewPackageViewModel 保存弹窗选择和输入。读取预设及参数定义可以用于显示默认值；构造界面、修改字段或切换选项不执行初始化、不合成完整方案，也不实时重算初始化派生结果。取消或关闭创建窗口保留当前方案。

点击“完成”后，读取模块准备所需数据，PackageInitializer 统一执行一次初始化。前端仅限制基本输入形式，例如数值框接受数字、枚举使用下拉选择；创建入口与 Initializer 不执行用户输入范围、必填、跨字段关系或几何合理性校验，不以业务校验结果阻止创建。

合成顺序为预设或基线、创建分支配置、用户提交参数、创建层栈计算。用户覆盖按是否提交决定，保留 `null`、`0`、`false` 以及与默认值相同的显式输入；数组整体替换，嵌套字段按约定路径更新，不隐式拼接层表或去除名单。

Chip Array 与 Wirebond PBGA 根据最终四层选择，按“普通预设 → 四层共用设置 → 对应预设差异 → 用户覆盖 → 层栈计算”合成。SOP 与 PQFP 的露出焊盘设置同样在用户覆盖之前应用。弹窗内切换创建选项不读取对应小契约或重新初始化。

用户提交的层表具有优先级，层栈计算不覆盖该层表，也不改变焊球布局和材料选择。负厚度等业务不合理值保留；缺失或无法参与运算的输入原样保留，无法计算的派生值留空，不静默修正或回填为合法值。问题在生成前统一报告，原始输入应能在编辑阶段定位和修改。

文件无法读取、JSON 无法解析、契约结构损坏或必要创建配置缺失属于读取和配置问题，与用户业务输入是否正确分别处理。

### 3.2 导入与编辑方案

```text
用户方案文件
    → JSON 解析、契约结构检查、显式版本迁移
    → ProjectDocument
    → 参数编辑

ProjectDocument + 用户编辑
    → 更新方案实际值
    → 更新方案修订号
    → 标记已有生成结果过期
```

预设与用户方案共用完整文件契约和读取实现，版本迁移只发生在文件读取边界。导入与生成完整方案不执行预设初始化、四层初始化、露出焊盘初始化或默认值回填；已保存的参数、层表与材料选择直接参与后续编辑和生成。

结构有效但业务参数存在问题的方案可以进入编辑。方案加载成功与生成成功分别表示文件可用和模型输入可用，不能互相替代。

### 3.3 统一生成模型

```text
用户请求生成模型
        ↓
ProjectDocument 的生成快照
    + PackageDefinition（含字段约束）
    + 已加载的 MaterialCatalog
    + 已加载的模型组目录
        ↓
ModelBuilder.Generate（Desktop 与 CLI 共用入口）
    → InputValidator：字段与材料检查
        → 按 TemplateId 调用家族检查
        → 家族检查组合适用的共用组件检查
    → 有 Error：返回 Model = null 与 Issues
    → 无 Error：准备本次构建状态与材料快照
    → 按 TemplateId 调用独立 Generator
    → 几何、等效物性、热源和元数据计算
    → PackageModel
    → ModelValidator：模型有效性、引用、功率、重叠
        ↓
GenerationResult { Model?, Issues }
    ├─ Desktop：预览、模型树、字段定位和几何高亮
    ├─ CLI：结构化问题、生成状态和退出状态
    └─ 导出入口：确认结果有效且属于当前方案
```

ModelBuilder 负责前校验、生成器分派、后校验和结果汇总。调用方准备运行数据，生成入口及各 Generator 不读取运行文件，不另设内容相同的生成服务。

InputValidator 读取参数定义检查必填、类型、有限数值、枚举、上下限、对象和表格结构，并检查材料选择与自定义物性。家族检查负责封装整体、组件之间的关系及特有分支；组件检查只负责实际跨家族复用的约束。家族之间不互相调用完整检查入口，共用算法按明确输入参数调用，不在组件内按全部家族切换行为。

能从参数直接确定的问题在前校验报告，例如焊球直径与节距、金属层位置与基板厚度、SOP 引脚数量奇偶关系。必须依赖实际生成结果的问题在后校验报告，不重复推导已检查的输入关系。

ModelValidator 检查模型非空、实体 ID 唯一、坐标有限、尺寸有限且为正、材料与模型组引用有效、输出物性有效、必要几何元数据有效，以及热源目标、功率和总功率守恒。空间关系检查在相应基础结构检查通过后执行，正体积重叠返回具体块对，共面接触不视为重叠。

生成器保留必要的计算前提保护。已知业务失败在发生处携带问题编号和消息，由生成入口转换为统一诊断；意外程序异常和文件访问失败在应用入口记录、呈现，不伪装成普通参数错误。

### 3.4 材料读取与等效计算

```text
材料记录、索引、别名和补充材料
    → MaterialCatalogReader
        解析来源字段、映射内部表示、检查基本物性
    → 只读 MaterialCatalog
        ├─ UI 浏览材料与选材
        └─ MaterialAssignments + CustomMaterials
            → 本次建模材料快照
            → MaterialMixer 等效计算
            → 模型实际使用材料快照
```

来源字段解析、各向同性导热率展开、别名与补充材料映射属于读取边界；等效物性混合属于 Core 业务计算。导热率、密度和比热要求有限且非负；温度系数与参考温度允许负值，仅要求有限。

`conduct_type` 决定生效字段：0 为常数各向同性，1 为温度相关各向同性，2 为正交各向异性。非当前类型的存储值保留，但不参与计算和物性检查；不依据方向值是否相等、系数是否为零猜测类型。

材料库基线只读。用户物性写入当前方案的 CustomMaterials，用户明确编辑的等效材料物性具有最终优先级；模型不反向修改材料库。读取、生效输入和计算输出共用基础物性判断，不建立独立的材料规则配置系统。

物性可信度提示与数值有效性分开处理。来源记录中密度或比热等于 1 的占位提示遵循材料可信度约定，不直接等同于加载失败；必要字段损坏或物性无效时明确报告，不静默替换默认材料。

### 3.5 导出

```text
当前方案与生成修订号
    → 确认结果未过期且 CanExport
    → ModelXmlExporter 接收 GenerationResult
    → 单位转换、局部材料编号与 XML 序列化
    → .packstudio.xml
    → 下游网格生成与数值求解
```

导出采用 PackStudio XML，表达轴对齐长方体块、已计算材料物性和按块关联的体热源。模型携带自足的材料快照，输出不依赖外部材料库；内部网格参数、辐射字段、非物理区域和监视点不进入输出。

Desktop 与 CLI 在导出前确认使用当前方案的生成结果；导出器检查结果是否允许导出，再按输出契约进行数值转换与序列化。导出不重新执行整套输入与模型校验，不修改模型或诊断。诊断保留在应用生成结果中，XML 内容以输出契约为准。

## 4. 项目与模块职责

项目依赖为 `PackStudio.Desktop → PackStudio.Core`、`PackStudio.Cli → PackStudio.Core`。Core 不引用 WPF；桌面和命令行只适配交互与协议，不复制核心业务流程。

| Core 模块 | 职责与边界 |
| --- | --- |
| Models | 方案、参数定义、计算模型、几何元数据、生成结果和诊断契约；不加载文件或执行校验。 |
| Initialization | 完成创建时合成参数、应用一次用户覆盖并派生创建层栈，保留不合理输入。 |
| Materials | 材料表示、只读目录、候选与覆盖选择、等效物性算法。 |
| Modeling | ModelBuilder 组织完整生成；BuildContext 持有本次可变构建状态，完成后发布只读 PackageModel。 |
| Modeling 的家族生成器 | 八类封装各自的结构组装、位置、尺寸、特有公式、热源和几何元数据。 |
| Modeling 的共用组件 | 实际跨家族复用的焊球、通孔、金属层、键合线和盖板算法。 |
| Validation | InputValidator、ModelValidator、基础数值判断和重叠算法；家族输入检查组合共用组件检查，直接返回问题列表。 |
| RuntimeData | RuntimeDataCatalog 组织运行目录、定义与创建配置的读取和缓存；MaterialCatalogReader 处理材料格式映射，完整预设正文复用方案读取入口。 |
| Projects | 完整方案读写和读取边界的显式版本迁移，预设与用户方案共用契约。 |
| Export | PackStudio XML 转换、序列化与文件输出。 |

| 应用模块 | 职责与边界 |
| --- | --- |
| Desktop/Shell | 主窗口、工作区、生成修订号和结果过期状态。 |
| Desktop/Features | 创建、参数、材料、预览和问题定位等功能各自的 View/ViewModel；NewPackage 只记录创建输入。 |
| Desktop/Controls | 多功能复用的数值编辑器、表格和矩阵控件，不创建缺失领域参数或计算几何公式。 |
| CLI | 研究请求和方案文件适配、初始化与生成入口调用、结构化输出、退出状态和文件导出。 |

ModelBuilder 按 TemplateId 显式分派八类 Generator，各家族负责完整封装组装。相似家族共享具体算法，不互相调用完整生成入口；包围尺寸和总高等家族特有元数据由对应 Generator 计算，不集中到一个跨家族通用生成分支。

输入校验采用相同的家族与组件组织原则，但不要求生成组件与检查文件一一对应。只服务一个家族的少量关系留在家族检查中，实际重复的规则才提取到共用组件。字段检查由统一入口执行一次，组件规则不重复执行字段类型与范围检查。

## 5. 生成结果与诊断契约

GenerationResult 包含可空的 PackageModel 和只读 Issues。模型非空只表示存在计算产物；预览和导出还需满足对应有效性条件。

ValidationIssue 包含 `Code`、`Severity`、`Stage`、`Message`、`ParameterPaths` 和 `EntityIds`。检查代码直接生成消息，UI 与 CLI 展示同一诊断；字段路径支持嵌套对象和表格行列，实体 ID 支持重叠块对及其他问题实体定位。核心检查不依赖 UI 标签或控件。

| 结果或事件 | 行为 |
| --- | --- |
| 完成创建 | 初始化并保留用户实际输入，进入参数编辑，不执行生成前业务校验。 |
| 输入校验有 Error | 不进入建模，返回 Model = null 和问题列表。 |
| 已知业务原因导致建模失败 | 返回 Model = null 和结构化问题；意外异常由应用入口处理。 |
| 模型校验只有 Warning | 允许预览与导出；正体积重叠按业务约定为 Warning，并提供具体块对。 |
| 模型校验有 Error | 禁止导出；只有满足基本渲染条件的模型才允许问题预览。 |
| 参数或材料等方案内容改变 | 生成结果过期，不能作为当前方案导出；生成期间修订号变化时不接纳过期结果。 |

校验汇总彼此独立的问题。字段类型、结构或数值检查失败后，跳过依赖该字段的关系检查，其他独立问题继续报告，避免同一根因产生大量衍生错误。无效模型与用户输入错误分别保留所属阶段，模型问题不一律归因于用户参数。

坐标有限、尺寸为正、必要引用有效及功率有效性属于固定阻断要求，不能通过运行数据降为警告。检查过程只读，不回填参数、不修复实体、不改变热源，也不向模型内累积警告。

## 6. 拆分与复用约束

- 一个构建过程只维护一份可变工作集合，发布结果承担只读输出职责，不增加内容相同的组装容器。
- 生成结果直接承载问题列表，不增加同内容报告包装和独立协调服务；预览与导出条件由结果提供简单属性。
- 简单运行数据共用目录加载入口；材料映射和方案读写有明确边界，不为每种 JSON 建立 Reader、接口和适配器多层包装。
- 目录与文件按实际复用和复杂度拆分，不为形式对称提前增加组件、接口、注册中心或转发模块。
- 重叠检测独立于家族组装，空间筛选和诊断数量控制依据实际模型规模与耗时演进。

架构文档记录职责和约束，具体文件清单、实现细节与测试结果由代码和 Git 表达。文档入口由根 README 统一索引。
